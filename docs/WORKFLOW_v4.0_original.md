# 高保真图片转可编辑PPT与PPT美化工作流 v4.0
## GPT 对话内可执行完整版

> 适用场景：
> 1. AI生成PPT页面图 → 可编辑PPTX；
> 2. PPT截图/拍照页 → 高保真可编辑PPTX；
> 3. 已有PPT → 保留内容、优化排版与视觉；
> 4. 多页课件/汇报PPT → 统一母版、视觉节奏与页面质量；
> 5. 工业、科研、教学、企业汇报类页面的批量重构与美化。
>
> 核心原则：**先判断任务，再拆页；先建立证据清单，再BUILD；先原生结构，后外部素材；先机器QA，再视觉QA；P0/P1不过，不交付。**

---

# 0. v4.0 的定位

v4.0 不是推翻 3.2，而是在 3.2 的基础上增加“GPT 对话内稳定执行”的工程机制。

3.2 的核心优势继续保留：

- 参考图作为版式真值；
- 标题、正文、卡片、箭头、表格等优先使用PPT原生对象；
- 标准图标优先调用SVG图标库；
- 复杂设备、产品、人物、场景按素材路由处理；
- 图片默认保持纵横比并完整显示；
- 正文不得低于12pt；
- 完成后必须导出预览并进行整页与局部检查。

v4.0 新增五个核心能力：

1. **任务路由**：严格复刻、美化、重设计、从零生成等任务不再混用规则；
2. **页面与元素清单**：每页建立 page_manifest，每个关键元素建立 reconstruction_inventory；
3. **设计Token与批量节奏**：保证几十页PPT前后一致，不出现风格漂移；
4. **机器可测QA + 视觉QA**：把“记得检查”升级为“必须经过质量门”；
5. **P0/P1/P2/P3错误分级**：明确哪些问题必须返工，哪些只是视觉优化。

---

# 1. 总目标

最终交付不是“看起来像PPT的图片”，而是：

- 可正常打开的PPTX；
- 结构尽可能原生可编辑；
- 页面视觉尽可能接近参考图或既定设计方向；
- 文本不溢出、不小于规定字号；
- 图片不拉伸、不截断主体；
- 箭头、流程、连接关系正确；
- 图标语义、风格、视觉重量统一；
- 批量页面的母版、色彩、间距、图片风格保持一致；
- 最终有预览、有QA、有返工记录。

# 2. 任务路由：开始前必须先选模式

每次任务只允许有一个“主路由”。若用户没有明确说明，则根据输入和目标自动判断。

## Route A｜严格复刻 Strict Reconstruction

适用：

- 图片 → 可编辑PPT；
- PPT截图 → 可编辑PPT；
- 用户要求“一模一样”“高保真”“不要重新设计”。

规则：

- 参考图是几何与视觉真值；
- 不主动改变布局；
- 不主动换配色；
- 不擅自调整流程方向；
- 仅在可读性、可编辑性或素材缺失导致无法复刻时做最小修正。

## Route B｜PPT美化 Beautification

适用：

- 用户已有PPT；
- 内容保持不变；
- 允许重新排版、统一层级、改善图片与图标、统一母版。

规则：

- **内容语义不改，视觉结构可改**；
- 允许重新组织卡片、图文比例、留白、对齐；
- 可以统一色彩、圆角、阴影、图标、图片风格；
- 不得因为“美化”擅自删掉关键内容；
- 高密度页面允许拆页，但应先说明。

## Route C｜重新设计 Redesign

适用：

- 用户允许重构视觉风格；
- 原PPT仅作为内容来源；
- 可以大幅重排结构。

规则：

- 先做2–3个设计方向；
- 通过样张后再批量生成；
- 原页面不再作为严格几何真值。

## Route D｜从零生成 New Deck

适用：

- 只有主题、大纲、Word、论文、Markdown等内容；
- 需要生成完整PPT。

规则：

- 先定内容结构，再定设计系统；
- 不直接跳到逐页排版；
- 先制作代表页和母版，再批量展开。

## Route E｜图片型幻灯片 Image-first Slides

适用：

- 更强调视觉冲击；
- 页面允许以大图或AI生成视觉为主；
- 可编辑性不是核心指标。

规则：

- 必须与“可编辑PPT”明确区分；
- 不能用整页图片冒充可编辑重构。

## Route F｜演讲型PPT Presenter-first

特点：

- 低文字密度；
- 强视觉锚点；
- 重点信息一屏一结论；
- 可附演讲者备注。

## Route G｜阅读型PPT Document-style

特点：

- 信息密度相对更高；
- 页面需具备自解释能力；
- 适用于教学、研究汇报、项目材料。

# 3. 输入质量门槛

开始BUILD前先检查输入。

## 3.1 页面是否完整

不得把以下内容当作PPT本体：

- PowerPoint/WPS/浏览器边框；
- 手机状态栏；
- 播放器按钮；
- 鼠标指针；
- 选中框、旋转点、裁剪框；
- 浮动工具栏；
- 截图软件边框。

轻微外围UI可自动忽略；若关键内容被遮挡，则标记 blocking_issue。

## 3.2 页面比例

优先统一为：

- 16:9；
- 或严格沿用原PPT比例。

同一批次若同时出现 16:9、4:3、竖版页面，必须先确认是否需要统一。

## 3.3 文字可辨识度

关键文字无法可靠识别时：

- 不得猜测；
- 标记低置信度；
- 必要时要求提供原PPT、PDF或更清晰图片。

## 3.4 图表与数据

若数据不能完整识别：

- 不得伪造数据；
- 不得“画一个看起来差不多”的原生图表；
- 可以保留源图形，或标记为 manual_required。

# 4. 批量执行规模：保证质量的默认阈值

GPT对话可以连续完成几十页甚至整套PPT，但**不建议一次BUILD太多页面**。

## 4.1 图片 → 可编辑PPT

最佳：**3–5页/批**。

- 简单页面：5–8页/批；
- 普通页面：3–5页/批；
- 复杂流程、工业设备、UI、多连接线页面：1–3页/批；
- 不建议单批超过8页；
- 高保真任务不建议单批超过10页。

## 4.2 已有PPT美化

最佳：**8–12页/批**。

- 高度统一的教学课件：10–15页/批；
- 普通美化：8–12页/批；
- 页面差异大、图片多、需要大幅重排：5–8页/批；
- 不建议单批超过15–20页。

## 4.3 代表页冻结机制

大批量任务默认：

1. 先读完整套内容；
2. 选择2–3页代表页；
3. 生成样张；
4. 冻结 Design Token；
5. 分批BUILD；
6. 每批QA；
7. 最后做整套缩略图墙检查。

示例：48页PPT美化

- 1–3页：试样/方向确认；
- 4–12页；
- 13–21页；
- 22–30页；
- 31–39页；
- 40–48页；
- 最终全局QA。

示例：48张图片转PPT

- 1–3页：试样；
- 后续每批4–5页；
- 最后全局QA。

# 5. page_manifest：页面级施工档案

每页开始前建立页面清单。

```json
{
  "page_id": "slide_001",
  "source_type": "image / screenshot / pptx / pdf",
  "route": "strict_reconstruction",
  "aspect_ratio": "16:9",
  "layout_family": "title-cards / split / process / matrix / full-image / table / mixed",
  "content_density": "low / medium / high",
  "complexity": "low / medium / high",
  "risk": "low / medium / high",
  "blocking_issue": null
}
```

page_manifest 用于控制：

- 页面比例；
- 任务模式；
- 页面复杂度；
- 是否需要分批；
- 是否允许自动继续；
- 是否需要人工确认。

---

# 6. reconstruction_inventory：元素级证据清单

每页必须把关键元素拆成可追踪对象。

```json
{
  "element_id": "s001_title_01",
  "family": "native_text",
  "bbox_norm": [0.06, 0.07, 0.72, 0.09],
  "text": "页面标题",
  "realization": "ppt_native_textbox",
  "editable": true,
  "confidence": 0.96,
  "layer": "native_text",
  "qa": "PASS"
}
```

## 6.1 family 分类

- `native_text`：标题、正文、标签、页码；
- `native_shape`：卡片、编号块、色块、分隔线；
- `native_connector`：箭头、流程线、连接线；
- `native_table_chart`：可验证数据的表格和图表；
- `local_svg_icon`：标准SVG图标；
- `source_graphic_exact`：需要保持原样的源图形；
- `registered_image_layer`：设备、产品、人物、机器人、场景；
- `decorative_native`：点阵、纹理、简单装饰线；
- `manual_required`：无法可靠自动重构的元素。

## 6.2 置信度

建议：

- ≥0.90：可自动执行；
- 0.75–0.89：执行后重点QA；
- 0.60–0.74：建议先验证；
- <0.60：核心元素不得猜测。

# 7. 页面几何拆解

严格复刻模式下，参考图是几何真值。

记录：

- Slide Size；
- 页面边界；
- 标题 x/y/w/h；
- 副标题 x/y/w/h；
- 页码位置；
- 卡片 x/y/w/h；
- 图片 Slot；
- 图标 Slot；
- 表格区域；
- 箭头起点/终点；
- 总结条区域；
- 主要留白区。

坐标建议：

- 统一使用英寸；或
- 0–1标准化坐标。

严格复刻任务不得因为“更好看”而擅自改变核心几何关系。

# 9. 页面元素路由

## A类｜PPT原生可编辑对象

包括：

- 页码；
- 导航；
- 主标题/副标题；
- 标题强调线；
- 卡片；
- 编号块；
- 流程节点；
- 箭头；
- 连接线；
- 分隔线；
- 表格；
- 可重建图表；
- 总结条；
- 说明文字。

原则：**能用原生对象实现，就不用截图。**

## B类｜标准图标

目标、定位、数据库、齿轮、盾牌、勾选、监控、云、服务器、芯片、仓储、物流、安全、质量、成本、效率等。

优先级：

**项目本地SVG图标库 > 用户自定义SVG > 成熟公开SVG > PPT原生几何 > 原图干净提取**。

标准图标默认禁止AI生成。

## C类｜复杂设备/产品/工业实物

PLC、工控机、机器人、机床、传感器、仪表、相机、电机、工件、生产线等。

优先级：

**原图干净提取 > 本地真实素材 > 官方/开放许可真实图片 > AI生成 > 相近替代**。

## D类｜复杂场景/UI

MES、SCADA、监控界面、工厂全景、车间、软件页面、生产线小场景等。

优先级：

**原图干净提取 > 官方真实界面/真实素材 > 开放许可场景 > AI近似视觉**。

## E类｜装饰元素

点阵、浅灰几何线、纹理、波纹、边缘光、简单科技线等。

优先使用PPT原生Shape重绘。

## F类｜图表/数据/表格

数据明确：重建为原生图表/表格。

数据不完整：不得伪造，保留源图或标记 manual_required。

# 10. 本地图标库调用机制

若项目已提供SVG图标库、manifest、语义索引或别名表，则优先使用。

检索流程：

**语义识别 → 关键词扩展 → 候选检索 → 形态筛选 → 风格筛选 → 颜色适配 → 视觉尺寸适配 → 插入 → QA**

判断标准：

1. 语义准确；
2. 形态接近参考；
3. 与同页其他图标同风格；
4. 视觉重量接近；
5. 线宽一致；
6. 细节不过度复杂；
7. 基线对齐。

禁止：

- emoji冒充图标；
- 符号字体冒充图标；
- 同一页混用线性、填充、3D、卡通图标；
- 有合适SVG时重新AI生成标准图标。

---

# 11. 图片与复杂素材处理

## 11.1 主体完整

设备、人物、机器人、产品、工件、场景核心主体必须完整。

默认保留主体四周5%–10%安全边距。

主体直接贴边或被裁切，默认不合格。

## 11.2 禁止整卡裁剪

只提取真正需要的图片主体。

不得把以下元素一起裁入：

- 卡片边框；
- 背景底色；
- 阴影；
- 标题；
- 说明文字；
- 分隔线；
- 虚线框。

## 11.3 图片插入规则

默认 `contain`：

- 保持纵横比；
- 完整显示；
- 居中；
- 宁可留白，不裁主体。

`cover` 仅限：

- 全幅背景；
- 大场景；
- 明确需要铺满的照片。

即便使用cover，也不得裁掉核心主体。

# 12. 字体、字号、段落

默认中文字体：微软雅黑 / Microsoft YaHei。

建议：

- 主标题：24–34pt；
- 模块标题：16–20pt；
- 正文：12–16pt；
- 标签：12–16pt；
- 表格正文：≥12pt；
- 流程节点：≥12pt。

硬性规则：

**正文、流程节点、卡片说明、表格正文不得低于12pt。**

禁止 PowerPoint AutoFit 自动缩成小字。

文字放不下时按顺序：

1. 调整换行；
2. 精简冗余；
3. 调整内部留白；
4. 微调容器；
5. 美化任务可拆页；
6. 严格复刻任务如必须改变，应标记偏差。

多行正文建议保持1.3–1.5倍视觉行距。

两行以上说明段优先左对齐；短标签和数字指标可居中。

---

# 13. 箭头、连接线、流程

必须检查：

- 单向/双向；
- 箭头方向；
- 虚线/实线；
- 粗细；
- 起点终点；
- 是否真正连接节点；
- 是否穿过文字；
- 是否被图片遮挡。

优先使用PPT Connector。

严格复刻模式下：

**不得根据业务理解擅自修正参考图中的方向。**

若怀疑参考图逻辑错误，应先标记，不私自改动。

---

# 14. 图层栈

建议采用固定图层：

1. `base`：背景、母版、底纹；
2. `midground`：大卡片、容器、色块；
3. `connector`：流程线、箭头；
4. `subject`：设备、图片、产品、场景；
5. `foreground`：徽章、标签、强调元素；
6. `native_text`：标题、正文、页码、注释。

原则：

- 连接线尽量在节点后方；
- 文本尽量位于最上层；
- 不让图片盖住箭头；
- 不让阴影压住正文。

---

# 15. 正式 BUILD 顺序

推荐顺序：

1. 页面尺寸；
2. 背景；
3. 母版/页码/导航；
4. 主标题/副标题；
5. 主体卡片/矩形/容器；
6. 表格/流程节点；
7. 箭头/Connector；
8. 正文；
9. SVG图标；
10. 设备图/场景图/产品图；
11. 底部总结条；
12. 装饰元素；
13. 局部对齐修正。

原则：**先原生结构，后外部素材。**

# 16. 美化模式专用流程

PPT美化不能直接逐页“自由发挥”。

## 16.1 全套扫描

先检查：

- 页数；
- 页面类型；
- 标题层级；
- 配色；
- 图片风格；
- 图标风格；
- 常见版式；
- 信息密度；
- 哪些页面最差；
- 哪些页面最有代表性。

## 16.2 代表页选择

至少选择：

- 1页封面/章节页；
- 1页常规内容页；
- 1页复杂内容页。

## 16.3 设计方向闸门

若用户没有给定风格，可提供2–3个方向，例如：

- A：稳健学术风；
- B：科技工业风；
- C：极简高级风。

注意：

- 只在美化/重设计任务中使用；
- 严格复刻任务跳过；
- 用户确认后冻结Token再批量。

## 16.4 内容保护

美化任务默认：

- 不删除核心内容；
- 不篡改数字；
- 不改变结论；
- 不擅自补充事实；
- 只优化视觉层级与表达结构。

---

# 17. 单页 QA：素材级、结构级、视觉级

## 17.1 素材级QA

图标检查：

- 语义；
- 风格；
- 颜色；
- 视觉重量；
- SVG渲染；
- 基线。

图片检查：

- 主体完整；
- 是否接触边缘；
- 是否有残影；
- 是否带多余文字；
- 是否带卡片边框；
- 是否模糊；
- 比例是否正常；
- 语义是否正确；
- 是否适配Slot。

结果：`PASS / FIX / REJECT`。

关键素材未PASS，不得进入最终BUILD。

## 17.2 机器QA

可以程序化检查的项目优先自动检查：

- 元素是否越界；
- 文本框是否溢出；
- 是否存在正文<12pt；
- 图片纵横比是否异常；
- 图片是否超出Slot；
- 元素是否发生异常重叠；
- 是否有不可见对象；
- 是否存在过大的隐藏对象；
- 是否出现意外空白页；
- 页面尺寸是否统一。

## 17.3 整页视觉QA

渲染整页预览后检查：

- 标题位置；
- 母版元素；
- 卡片比例；
- 对齐；
- 留白；
- 箭头方向；
- 文字溢出；
- 图标大小；
- 图片完整性；
- 总结条；
- 是否接近参考图/既定设计方向。

## 17.4 局部放大QA

重点放大：

- 小图标；
- 小设备图；
- 右上角徽章；
- 底部缩略图；
- 页面宽度<10%的图片；
- 流程连接点；
- 表格小字；
- 图片边缘。

原则：**整页看着正常，不代表局部合格。**

---

# 18. 批量 QA：检查整套PPT而不是只看单页

对于8页以上任务，最终必须做“缩略图墙”或等效的整套检查。

检查：

- 标题字号是否漂移；
- 页边距是否漂移；
- 卡片圆角是否漂移；
- 图片位置是否过于机械重复；
- 连续多页是否都是相同版式；
- 强调色是否失控；
- 图标风格是否变化；
- 章节页是否有节奏；
- 复杂页面是否异常拥挤；
- 某些页面是否突然过空；
- 页面视觉重心是否连续偏一侧。

美化任务尤其需要这一层。

# 19. 错误等级 P0 / P1 / P2 / P3

## P0｜阻断交付

出现任一项必须返工：

- 整页截图冒充可编辑PPT；
- 核心文字不可编辑且无理由；
- 正文<12pt；
- 页面比例错误；
- 核心图片主体被截断；
- 图片被严重拉伸；
- 箭头方向错误；
- 双向箭头变单向；
- 数据被伪造；
- 页面内容缺失；
- 大量文本溢出；
- PPTX无法正常打开。

## P1｜交付前必须修

- 元素明显错位；
- 图标语义错误；
- 图标风格明显不统一；
- 图片比例轻度异常；
- 文本轻度溢出；
- 卡片间距明显不齐；
- 图片存在二次裁切；
- 连接线穿过文字；
- 母版元素不一致。

## P2｜建议优化

- 留白略不均；
- 视觉重量略失衡；
- 单页节奏普通；
- 对齐精度还有提升空间；
- 图片与文字比例可以更优。

## P3｜可选增强

- 动效；
- 演讲稿；
- 多主题版本；
- 额外插画；
- 交互式HTML预览。

# 21. GPT 对话内标准执行协议

用户发送图片、PPT、PDF或截图后，默认执行：

### Phase 1｜判断

- 确认任务路由；
- 判断页面数量；
- 判断复杂度；
- 决定批次大小；
- 检查是否需要样张闸门。

### Phase 2｜拆解

- 建立 page_manifest；
- 建立 reconstruction_inventory；
- 记录几何；
- 分类元素；
- 识别阻塞项。

### Phase 3｜设计冻结

严格复刻：从参考图提取设计关系。

美化/重设计：

- 先做代表页；
- 冻结 Design Token；
- 再批量执行。

### Phase 4｜BUILD

- 原生文字；
- 原生Shape；
- Connector；
- SVG图标；
- 复杂图片；
- 装饰元素。

### Phase 5｜Render

- 导出整页预览；
- 必要时导出缩略图墙；
- 必要时导出局部放大图。

### Phase 6｜QA

- 机器QA；
- 整页视觉QA；
- 局部QA；
- P0/P1检查。

### Phase 7｜返工

- P0必须全部清零；
- P1原则上全部清零；
- P2视时间与用户需求优化；
- P3按需执行。

### Phase 8｜交付

至少交付：

- PPTX；
- 页面预览图；
- 生成脚本。

批量、高风险或图片转PPT任务建议额外交付：

- reconstruction_inventory.json；
- QA report；
- 缩略图墙。

# 22. 失败处理与阻塞规则

以下情况不得“硬做”：

- 关键文字不可读；
- 数据图表无法识别；
- 页面被严重遮挡；
- 参考图比例无法判断；
- 用户要求“完全一致”，但关键素材缺失；
- 原PPT依赖特殊字体且无法替代；
- 复杂源图形无法可靠重建且又不允许保留图片。

处理方式：

1. 标记具体阻塞项；
2. 给出最低风险替代方案；
3. 不把推测当作事实；
4. 不伪造不可见内容。

# 26. v4.0 一句话总原则

> **先路由，后拆解；先证据清单，后BUILD；先原生结构，后外部素材；严格复刻不擅自设计，美化任务先冻结风格；图片完整显示，正文不低于12pt；每批都Render + QA，P0/P1不过不交付；整套任务最后再做全局一致性审查。**

# 27. 建议的后续升级方向：v4.1

v4.0 已经是一套完整的执行规范，但仍有一部分QA依赖人工视觉判断。

v4.1 不建议继续堆文字规则，而应重点实现自动化：

- 自动统计所有文本字号；
- 自动检测页面越界；
- 自动检测异常重叠；
- 自动检测文本溢出；
- 自动输出可编辑率；
- 自动生成缩略图墙；
- 自动生成P0/P1报告；
- 自动检查图片长宽比异常；
- 自动生成每页inventory；
- 自动对比参考图与渲染图的结构差异；
- 对P0/P1进行自动返工或定位。

当这些检测真正代码化后，工作流才会从“规范化”进一步升级为“闭环自动化”。
